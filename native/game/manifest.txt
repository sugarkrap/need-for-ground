# Functions to import from decompiled/ and run natively.
#
# This file is a list of addresses and names - facts about the binary, of the
# same kind NOTES.md already records. The *code* those addresses hold is a
# derivative of the copyrighted game binary and is never committed (see
# .gitignore, which excludes decompiled/ and native/game/generated/).
# native/tools/import_decompiled.py turns this list plus your local
# decompiled/ output into compilable translation units.
#
# Format:  <address>  <symbol>  <kind>  <one-line note>
#
# kind is documentation, not behaviour:
#   crt   statically-linked MSVC runtime code, verifiable against libc
#   game  the game's own logic
#
# Only self-contained functions are listed for now - no calls out, no globals -
# because those can be run and checked in isolation. Anything touching a DAT_
# global or calling another FUN_ needs either the whole call graph ported or the
# hybrid PE-loader path, and neither is a prerequisite for proving this one.

0x75c440   _strncpy       crt   MSVC's word-at-a-time strncpy (0x7efefeff zero-byte trick)
0x75d260   _strrchr       crt   reverse character search
0x401000   FUN_00401000   game  dword-then-byte memcpy (inlined all over the engine)
0x43ce40   FUN_0043ce40   game  3D euclidean distance between two float[3]
0x48b710   FUN_0048b710   game  dot product into a float[4], preserving y/z/w

# Tried and deliberately excluded. Each fails for a different reason, and the
# three together are a fair summary of what "the decompiler output is not
# compilable C" actually means in practice:
#
# 0x75c800  shortsort   Ghidra recovered the signature wrongly. The body reads an
#                       `undefined1 *in_EAX` that is never assigned - the real
#                       function takes a parameter Ghidra did not find, so the
#                       ported code would index off an uninitialised register.
#                       Needs the signature corrected in Ghidra and re-exported.
#
# 0x75d928  __ftol      The original takes its argument on the x87 register stack
#                       (`float10 in_ST0;` in the output), which is MSVC's private
#                       convention for this helper and has no C spelling at all.
#                       Needs a hand-written asm thunk, or replacing with a call
#                       to the compiler's own float-to-int conversion.
#
# 0x75d860  __isnan     Uses Ghidra's field-slice syntax on a scalar - `_X._6_2_`
#                       for bytes 6..7 of a double. Not C. Needs the double
#                       re-typed as a union in Ghidra, or the slices rewritten by
#                       hand as shifts.
